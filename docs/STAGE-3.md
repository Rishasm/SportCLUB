# Этап 3 · Вход, абонемент и бронирование

На этом этапе реализован сквозной пользовательский сценарий SportCLUB. Интерфейс обращается к API через Gateway. На этапе 3 использовались файловые базы H2. Настройка текущей базы PostgreSQL описана в [README](../README.md).

## Что работает

- Регистрация, вход, выход и восстановление сессии после обновления вкладки.
- Хеширование паролей BCrypt, подписанные JWT на 2 часа, защита личных API.
- Три тарифа и явно подтверждаемая учебная активация без оплаты.
- Расписание на ближайшие семь дней, фильтры даты и направления, карточки тренеров.
- Межсервисная проверка абонемента через Eureka перед бронированием.
- Запись, отображение в кабинете, отмена и повторная запись.
- Контроль вместимости в транзакции с `SELECT ... FOR UPDATE` и уникальностью пары занятие/клиент.
- Изоляция личных записей: клиент не может посмотреть или отменить чужие бронирования.
- Миграции V2 для баз клиентов и клуба; существующие базы V1 обновляются без удаления данных.

## Проверки

Общая Maven-сборка: **28 тестов, 0 ошибок, 0 падений**.

Покрыты регистрация и нормализация email, хранение хеша вместо пароля, неверные учётные данные, подписание JWT, профили разных клиентов, абонементы и их истечение, конкурентная активация, запись и отмена, прошедшее занятие, ошибки межсервисной проверки и конкурентная борьба за одно последнее место.

Реальный стенд проверен скриптом `scripts/test-booking-flow.ps1`: регистрация → абонемент → запись → кабинет → повторный вход → отмена → повторная запись. Запросы без входа, без абонемента, дубликаты и отмена чужой записи отклоняются. Активные тестовые бронирования отменяются.

Браузерная проверка: регистрация через форму, выбор тарифа и подтверждение, выбор занятия, кабинет, перезагрузка вкладки, отмена, выход и повторный вход. Проверены экраны главной, тарифов, расписания, кабинета, входа и регистрации при ширинах 1280, 768, 390 и 320 px. JavaScript-ошибок и горизонтального переполнения не обнаружено.

Отдельно проверен полный перезапуск семи приложений: созданные аккаунт, пароль, абонемент и бронирование сохранились. После перезапуска выполнен вход, проверены те же идентификаторы записей, тестовое бронирование отменено. В локальном H2 включён `WRITE_DELAY=0` для синхронной записи изменений.

## Запуск

```powershell
.\scripts\start-local.ps1 -Build
```

Открыть [SportCLUB](http://localhost:8080/). Для знакомства доступен демонстрационный аккаунт `demo@sportclub.local` / `SportClub123!`; также можно зарегистрировать собственный учебный аккаунт.

На этом этапе проверялся локальный запуск с H2. Дневники тренировок и личных показателей описаны в отчётах следующих этапов.
